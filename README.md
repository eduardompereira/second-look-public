# Second Look — see what you missed

**Second Look** is a post-match format for ice hockey, built for the **SIC DataHack 2026** (Sport Innovation Challenge).
Fans check the score and leave. Second Look answers the score first, then offers one more interaction: watch the winning
goal again, make your own read on the frozen frame (never timed, never graded), look again, and only then does the data
name and measure what you missed. Two short stories, then three optional investigations that each open from the story
moment they belong to and always bring you back there.

### What you can do in this edition

| Feature | What the fan gets |
|---|---|
| Two guided stories | Watch → your read (never timed, never graded) → look again → one measured reveal → what to look for next time |
| Three investigations (*Look around*) | Every shot attempt on one goalie (map), the last pass before two saved chances, who stayed on the ice; each opens from its story moment and returns there |
| **Discovery points** | A quiet points pill at moments of choice. Points come only from what you discover, never from whether a read was right. No sharing, nothing leaves the page |
| **Two-rink Follow the Play** | The two chances side by side on two rinks, a neutral guess before the second reveal, the shared last passer named once |
| **The other side** | From the shot map, *And the other side?* opens the other team's attempts on the other goalie, only after the story moment it would otherwise spoil |
| **Player match cards** | Tap a named player in a finding: a few counts from this (fictional) final, by period where the data has them |

Every finding shows one result, its comparison group and the limit that keeps it honest (e.g. *a last pass shows who had
the puck, not who made the chance*). Methods and definitions are documented in `docs/`, not in the fan's way.

> **This is the public edition. It runs on a fictional match.** Teams (Harbour HC, Ridge Academy), players, events, times,
> positions, ratings and statistics are generated by `tools/make_fictional_fixtures.py` from one fixed seed. The video
> is generated placeholder footage. Nothing in this repository is real match data or footage. Per the organiser's
> instructions, the competition's tracking data and match video are used only in our private build and in the jury
> demo (see [docs/DATA_AND_RIGHTS.md](docs/DATA_AND_RIGHTS.md)).

## Run it

Requirements: Node 20+, Python 3.10+, `ffmpeg`, Pillow (`pip install pillow`).

```bash
npm run fixture:setup     # installs the fictional payload, placeholder stills and generated placeholder clips
npm run dev               # → http://127.0.0.1:5199/
```

Open it on a phone-sized window. `?clarity=0` shows the earlier pacing (beats advance on their own); the default waits for
your tap after each evidence beat.

## Test it

```bash
npm run qa:install        # once: Playwright + Chromium
npm run test:public       # syntax · fixture lineage · payload contract · publish gate · package security gate · browser journeys
npm run gate:publish      # the publish gate alone
```

The browser journeys walk both stories, the three investigations, return-to-story, reload, deep links and keyboard use
on the fictional match. They test the product's behaviour; **they are not evidence about any real match.**

## What is here

| Path | What |
|---|---|
| `prototype_wave3b/experience_rc3/` | The app: a zero-dependency static web app + a tiny Node server. Stories, the video stage, the investigations ("Look around") |
| `tools/make_fictional_fixtures.py` | Fictional-match factory (seeded; reads no file) |
| `fixtures/` | The generated payload and the placeholder-media setup |
| `tests/` | Payload contract (the fixture has the same shape as the private payload) |
| `tools/public_gate.py` | Publish gate: allow-list, no media/data, fixture lineage, generator independence, fictional roster, disclosure, history |
| `src/rc3/` | Package builder and its security gate (password-protected deployment, fail-closed), journey tests |
| `docs/` | How it works, what this public edition contains, data and rights |

**Not here, by design:** the data pipeline that turns the competition's match export into the app's payload (it embeds
match-specific constants), the real payload, the match clips and stills, our research notes and test sessions. They stay
in our private repository, which we can share with the organisers on request. See
[docs/PUBLIC_EDITION.md](docs/PUBLIC_EDITION.md) for exactly what differs from the private build.
